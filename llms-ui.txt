# Rapise UI and Workflows

> A map of the Rapise desktop IDE and of the tasks people do in it, for an AI assistant that answers questions about Rapise. It names the windows, menus, dialogs and buttons as Rapise shows them, says which feature solves which problem, and points to the documentation section with the details. It describes Rapise 9.1; "(9.1+)" marks features that older versions lack.

How to read the links: every link target is a documentation location, a page path with an optional `#section`, for example `Guide/object_tree#filtering`. The same section is on the web at https://rapisedoc.inflectra.com/Guide/object_tree/#filtering. This guide only says where things are and when to use them; read the linked section before giving step-by-step instructions, and quote labels exactly as written there.

Menu paths are written `Menu > Item`. Button and field names are in backticks.

## 1. Rapise in Short

- Rapise records and plays back UI tests for web (Selenium WebDriver), desktop Windows applications, mobile (Appium), and also tests web services (REST/SOAP) and manual tests. [Overview](Guide/overview) · [Technologies](Guide/technologies)
- A test is a folder with a `.sstest` file. Its steps are written either in RVL (Rapise Visual Language, a spreadsheet `Main.rvl.xlsx`) or in JavaScript (`Main.js`). Learned UI objects live in `Objects.js` (the object repository). [Understanding the Script](Guide/understanding_the_script) · [RVL](Guide/visual_language)
- Since Rapise 8 the normal way to work is a Testing Framework: one root test that holds many test cases, Page Objects / Modules, shared files, parameters and configurations. Older sub-tests are deprecated. [Frameworks](Guide/Frameworks/frameworks) · [Framework intro](Intro/framework) · [Tests and Sub-Tests](Guide/tests_and_sub_tests)
- Rapise works with Spira (SpiraTest/SpiraTeam/SpiraPlan): tests are stored and versioned there, test sets are scheduled there, and RapiseLauncher runs them on automation hosts. [SpiraTest Integration](Guide/spiratest_integration) · [Spira Dashboard](Guide/spira_dashboard_2)
- AI features: AI Commands in RVL, AiTranslator, self-healing with SmartAction, AiRobot, AiTester, chats in the AI Dashboard, agentic chat with MCP tools. [AI Overview](AI/overview)
- A first tour of the window: [Know Your Way Around](Intro/orientation). Shortcuts and common actions on one page: [Cheat Sheet](Guide/cheatsheet).

## 3. Start Working

### Create or open a test

- New standalone test: `File > Create New > New Test`. The Create New Test dialog asks where to keep it (Spira or `Create Locally...`), the `Test name`, `Folder` and `Test type` (Basic, Manual, Mobile, Web); then the Choose Scripting Language dialog asks RVL or JavaScript. [Create New Test Dialog](Guide/create_new_test_dialog) · [Scripting Choice](Guide/scripting_choice_dialog) · [Create a New Test](Guide/create_a_new_test)
- New framework: `File > Create New > Test Automation Framework`: name, folder, primary type of test. [Creating a New Testing Framework](Guide/Frameworks/frameworks#creating-a-new-testing-framework)
- Add a test case to a framework: `File > Add To Framework > Test Case`, or `Create Test Case` on the Test Cases node of the Object Tree. [Creating a Test Case](Guide/Frameworks/frameworks#creating-a-test-case) · [Test Cases context menu](Guide/object_tree#test-cases-root-context-menu)
- Open: `File > Open`, `File > Recent Tests`, or `File > Open Test from Spira`. [Open a Test](Guide/open_a_test)
- Samples: Start Page, `Fetch Samples`. [Start Page](Guide/start_page#purpose) · [Samples Index](Guide/sample_tests)
- Tutorials to follow step by step: web [RVL](Guide/tutorial_record_and_playback) / [JavaScript](Guide/tutorial_web_using_javascript), desktop [RVL](Guide/twodialogs_sample) / [JavaScript](Guide/tutorial_windows_using_javascript), mobile [Android](Guide/mobile_testing_android) / [iOS](Guide/mobile_testing_ios), web services [REST](Guide/tutorial_web_services_rest) / [SOAP](Guide/tutorial_soap_web_services), [manual](Guide/tutorial_exploratory_testing).

### RVL or JavaScript

- RVL is a spreadsheet of steps that needs no programming and suits most test cases; JavaScript is more flexible (loops over arrays, strings, JSON, web services). They mix: RVL calls JavaScript functions from `User.js` through the `Functions` object, and Page Objects can be either. [Choice of scripting](Guide/overview#choice-of-scripting-or-scriptless-rapise-visual-language-rvl) · [RVL vs JS for Page Objects](Guide/Frameworks/pageobjects#page-object-rvl-vs-js) · [Functions object](Guide/rvl_editor#functions-object)
- The default language for new tests is `Default Scripting Language` in `Settings > Global`. [Rapise Settings](Guide/options_dialog#settings)

## 4. Record and Learn

- `Record` (toolbar or `Test > Record`) opens the Recording Activity dialog. For web it first asks for the URL; for desktop it first shows Select an Application to Record; in a framework you first choose the test case (or Page Object) to record into. [Recording](Guide/recording) · [Recording Activity Dialog](Guide/recording_activity_dialog#how-to-open) · [Choose Test Case](Guide/test_to_play_selector#recording-and-playback)
- Recording Activity dialog: `Verify` Ctrl+1 (checkpoint on the object under the mouse), `Learn` Ctrl+2 (add the object under the mouse without an action), `SPY` Ctrl+5 (open a spy to learn hidden or covered objects), `Pause`/`Resume`, `Finish` Ctrl+3 (writes the steps), `Cancel` (discards). `Adv.>>` adds `Analog` Ctrl+4 and simulated-object rules. Right-click a recorded action: `Delete Action`, `Edit Action`, `Try Action`. [Standard mode](Guide/recording_activity_dialog#standard-mode-features) · [Advanced mode](Guide/recording_activity_dialog#advanced-mode-features) · [Context menu](Guide/recording_activity_dialog#context-menu)
- Recording again adds the new steps and objects to the test. [Multiple Recordings](Guide/multiple_recordings)
- Learn instead of record when you only need the object: hover it and press Ctrl+2; then use it in RVL or JavaScript. [Learn an Object](Guide/learn_object) · [Learning](Guide/object_learning)
- Desktop: Select an Application to Record lists running applications (`Refresh`, `Finder Tool`) and the library to use (`Auto` by default); the `Run Application` tab starts one. Ctrl+`Record` reopens it; Shift+`Record` opens library selection. [Select an Application](Guide/select_an_application_to_record_dialog) · [Choosing a Windows library](Guide/windows_applications#choosing-the-right-windows-library) · [Shortcuts](Guide/change_the_libraries_being_use#keyboard-shortcuts)
- Web: create the test with test type Web and a Selenium profile such as `Selenium - Chrome`; recording with Selenium needs Chrome or Edge, playback works in other browsers too. [Web tutorial](Guide/tutorial_record_and_playback#open-rapise-and-create-new-test) · [Selenium WebDriver](Guide/selenium_webdriver)
- Mobile: prepare Appium and a device, create a profile in `Settings > Mobile` and `Test URL` it, then `Record`; learn objects with Mobile Spy. [Mobile Testing](Guide/mobile_testing2) · [Preparing for Android](Manuals/Preparing_for_Android_Testing) · [Preparing for iOS](Manuals/Preparing_for_iOS_Testing)
- Drawing or signatures: `Adv.>>` > `Analog`. [Analog Recording](Guide/analog_recording)
- Checkpoints: `Verify` (Ctrl+1) opens Verify Object Properties: tick properties, set values; `Exists` and `Visible` check presence (6.6+). [Verify Object Properties](Guide/verify_object_properties) · [Checkpoints](Guide/checkpoints) · [RVL Assertions](RVL/Assertions)
- AI-assisted recording: tag a web test case `airecorder` so recorded and AI steps get self-healing SmartActions. See section 9, Self-Healing. [Enabling AI Recorder](Guide/web_self_healing#enabling-ai-recorder)

## 6. Run and Debug

- `Play` (toolbar, `Test > Play`) runs the test. In a framework it opens Choose Test Case: pick one or several test cases (8.1+), a `Configurations...` set (8.1+) and `Parameters...`. A test case's own `Play` in the Object Tree runs it directly; `Play All` / `Play All (Recursive)` on a folder runs a batch (skipping cases tagged `template` or `skip`). [Playback](Guide/playback#usage) · [Choose Test Case](Guide/test_to_play_selector) · [Test case menu](Guide/object_tree#test-case-context-menu) · [Test case tags](Guide/object_tree#test-case-tags)
- Run part of an RVL sheet: select rows, right-click `Play Selection`; or `Play From Here`, `Play This Sheet`. Shift+`Play` repeats the last selection. [RVL context menu](Guide/rvl_editor#context-menu) · [Replay RVL selection](Guide/playback#replay-rvl-selection)
- During playback the Test Execution Monitor shows progress with `Pause`, `Stop` (Shift+Ctrl+F12) and `Hide`; it can be turned off in Rapise Settings. [Execution Monitor](Guide/playback#test-execution-monitor)
- Repeat a test, change its entry point, stop or not on the first error: `Test > Test Settings` (`Iteration Count`, `EntryPoint`, `StopOnError`). [Test Settings: Execution](Guide/settings_dialog#execution) · [Advanced](Guide/settings_dialog#advanced) · [Change Test Entry Point](Guide/change_test_entry_point)
- More detail in the Output view: `Tools > Verbose Level` (`No Verbose`, `Level 1 (Minimal)` by default, `Level 2 (Normal)`, `Level 3 (Flood)`, `Level 4 (Overflood)`). [Verbosity Levels](Guide/verbosity_levels)
- Debug JavaScript: `Tools > Debugger` to enable, F9 for a breakpoint, `Play`, then F10/F11, Watch and Call Stack views, hover tooltips. [Internal Debugger](Guide/internal_debugger) · [Breakpoints](Guide/breakpoints) · [Control Execution](Guide/control_execution)
- Keep the browser or app open between runs and continue from the failed step: reconnect WebDriver or mobile sessions. [Reconnect WebDriver Session](Guide/selenium_reconnect) · [Reconnect Mobile Session](Guide/mobile_reconnect)
- Run outside the IDE: see section 11, Git, command line and CI.

## 7. Read Results

- After playback the report opens in the Report Viewer (unless `Show Report` is off in Test Settings); in a framework, a test case's `Last Report` in the Object Tree reopens it. Reports are `.trp` files under `Reports`, also written as `last.tap` and HTML. [Report Viewer](Guide/report_viewer) · [Automated Reporting](Guide/automated_reporting) · [Report Formats](Guide/automated_reporting#report-formats)
- Failed steps are red. Filter rows with the filter row (by status, text, custom criteria), group by dragging a column header, switch `Report > Plain | Hierarchical | Images`. [Report Filtering](Guide/report_filtering) · [Column Grouping](Guide/automated_reporting#column-grouping)
- Export: `Report > Export to HTML | Excel | PDF | XPS`. [Report menu](Guide/menu_and_toolbars#report)
- Screenshots of each step or on failure: `Test Settings` Screen Capture, or in a framework `Parameters...` > `Capture Execution`; `Include in Report` sends them to Spira. [Screen Capture](Guide/settings_dialog#screen-capture) · [Screenshots](Guide/screenshots)
- Write your own report rows and columns: `Tester.Message`, `Tester.Assert`, `Tester.SetReportAttribute`. [Writing to the Report](Guide/writing_to_the_report)

## 8. Objects and Locators

- Locators: how Rapise finds objects, and how to override locator parameters. [Object Locator](Guide/object_locator) · [XPath](Guide/xpath) · [CSS](Guide/css) · [UIAutomation Locators](Guide/uiautomation_locator) · [Java Locators](Guide/java_locator)

[Web Spy Settings](Guide/web_settings#different-types-of-xpath) · [Web Application Profile](Guide/web_app_profile)
- Move or copy objects between tests or into Page Objects: `Tools > Object Manager` (`Copy Right`, `Copy All Right`, `Move Right` 8.4+, `Remove Right`). [Object Manager](Guide/object_manager)
- Reuse an object definition as a template in a framework. [Object Templates](Guide/object_templates)

## 9. Self-Healing, SmartAction and Modernize

- When a web object is not found, SmartAction uses the object's description and AI vision to find it, the test goes on, and the new locator is saved to a `.jspatch` file. After the run the JSON Patch Editor lets you `Apply`, `Apply All for Object`, `Apply Pending for File`, `Apply All Pending`, `All Done`. [How Self-Healing Works](Guide/web_self_healing#how-self-healing-works) · [SmartAction](Guide/web_smart_action) · [JSON Patch Editor](Guide/web_smart_action#applying-patches-with-the-json-patch-editor)
- Turn it on for recording with the `airecorder` tag (per framework in the Web Test Setup dialog or per test case). It needs Inflectra.ai or your own AI provider. [Enabling AI Recorder](Guide/web_self_healing#enabling-ai-recorder) · [Self-Healing](Guide/web_self_healing)
- `Test > Modernize` (9.1+) re-heals all objects of a test at once and writes a patch to review. [Modernize Command](Guide/web_self_healing#modernize-command)
- A step that may or may not be needed (an optional popup): start its description with "Optional.". [Optional actions](Guide/web_smart_action#optional-actions)
- Switch healing off: `g_saDisableHealing = true` (for example in CI), or per object (9.1+). [Disabling Self-Healing](Guide/web_self_healing#disabling-self-healing) · [Command line](Guide/command_line#disabling-self-healing)
- RVL and JavaScript differ in where SmartAction data is stored. [Comparison](Guide/web_self_healing#comparison)

## 10. Browsers, Mobile Devices, Web Services, Other Technologies

- Browsers: Selenium profiles in `Settings > Selenium` (`Test`, `Duplicate`, `Create`, `Delete`; remote `URI`, `Chrome Specific` options also used by Edge, BrowserStack, local profiles 6.3+, `{Param}` placeholders 8.3+). Drivers are downloaded automatically (7.3+). `Tools > Chrome for Testing` downloads a fixed Chrome version and creates a profile for it, so browser updates do not break tests. [Selenium Settings](Guide/selenium_settings_dialog) · [Setting Up Selenium](Guide/setting_up_selenium) · [Setting Up Web Browsers](Guide/setting_up_web_browsers)
- Run in another browser: pick it in the profile dropdown and `Play`. Several browsers in one run: a framework Browser parameter with `Multiselect`. [Cross Browser Testing](Guide/cross_browser_testing) · [Browser parameter](Guide/Frameworks/parameters#browser-parameter)
- Older native browser profiles (not Selenium) are legacy; they are edited in `Settings > Browser`. [Browser Settings](Guide/browser_settings)
- Mobile: `Settings > Mobile` profiles (Appium URL, device clouds, `Test URL`). [Mobile Settings](Guide/mobile_settings_dialog)
- Web services: `Tools > Web Services` creates a `.rest` or `.soap` file; the REST editor's script steps create test code, the SOAP editor has `Invoke`, `Record`, `Verify`. [Web Service Testing](Guide/web_service_testing) · [REST Editor](Guide/rest_definition_editor) · [SOAP Editor](Guide/soap_definition_editor) · [Add Web Service](Guide/dialog_add_web_service)
- Desktop: [Desktop Testing](Guide/windows_applications) · Java [AWT/Swing](Guide/java_awt_swing_testing) / [SWT](Guide/java_swt) · [Qt](Guide/qt_framework_testing) · [Microsoft Dynamics](Guide/microsoft_dynamics) · [Salesforce](Guide/salesforce_com) · [Oracle Forms](Guide/oracleforms_testing) · [COM](Guide/com_testing_support) · [DLL](Guide/dll_testing)

## 11. Frameworks, Data, Spira, Git, Command Line and CI

### Framework structure

- Object Tree in a framework: Test Cases (create, import, play all, tags), Modules / Pages, Shared files. - Reusable actions (login, open module, add record): `File > Add To Framework > Module / Page Object`; in RVL each sheet is an action, its signature declares parameters (`DoLogin(user, /**string*/pwd)`); call it as `MyPage.DoLogin`; try it with `Invoke <Action>` in the Object Tree. Ready-made public Page Objects (8.2+). [Page Objects](Guide/Frameworks/pageobjects) · [RVL Action Parameters](Guide/Frameworks/pageobjects#rvl-action-parameters) · [Public Page Objects](Guide/Frameworks/pageobjects#public-page-objects)

- A framework stores its structure in `Framework.json` and `Parameters.json`; file layout for AI tools: [llms-framework.txt](https://rapisedoc.inflectra.com/llms-framework.txt).

### Parameters, configurations, data

- Framework parameters: Spira Dashboard `Parameters` view, `Add Parameter` (boolean, number, string, password, select, browser, mobile, datacolumn, environment 9.1+), `Add Input Data File`; read with RVL ParamType `testparam` or `Tester.GetParam`. [Parameters and Configurations](Guide/Frameworks/parameters) · [Parameter types](Guide/Frameworks/parameters#supported-parameter-types) · [Configurations](Guide/Frameworks/parameters#configurations)

[Data-Driven Testing](Guide/ddt) · [DDT intro](Intro/ddt) · [Maps](RVL/Maps) · [Loops](RVL/Loops#loop-map)

## 12. AI Features

### Set up

- `View > AI Dashboard` > `Settings`: `Provider` is `Inflectra.ai`, `Amazon Bedrock`, `Azure`, `OpenAI` or `Google`; fill its fields, choose a `Model ID` (a dropdown of tested models 9.1+), `Proxy` if needed, then `Test Model`. `Scope` is `global` or `local` (per framework, created with `local[create]`, overrides global). Shift+Ctrl+Q shows more settings. [AI Dashboard Settings](AI/ai_dashboard#settings) · [Model ID dropdown](AI/ai_dashboard#model-id-dropdown) · [Proxy](AI/ai_dashboard#proxy)
- Inflectra.ai (8.6+) needs no keys: Rapise connected to a Spira where Inflectra.ai is enabled. From 9.1 it also serves AiTranslator and AiRobot. [Inflectra.ai](AI/ai_dashboard#inflectraai) · [9.1 enhancements](AI/ai_dashboard#rapise-91-enhancements)
- Own provider details: [Amazon Bedrock](AI/ai_dashboard#amazon-bedrock) · [Azure](AI/ai_dashboard#azure) · [OpenAI](AI/ai_dashboard#openai) · [Google](AI/ai_dashboard#google)
- Where AI files are and which to commit (`options.json`, `AIPrompt.txt`, `AIExamples.txt`, `ai.commands.json`). [Framework folders](AI/ai_dashboard#framework-folders) · [Source control](AI/ai_dashboard#source-control)

### AI Dashboard chats

- `Chats` lists past chats; a new chat asks for a workflow; starred chats go to `Snapshots`. [Chats](AI/ai_dashboard#chats) · [Snapshots](AI/ai_dashboard#snapshots)
- Workflows: `AI Chat` (general, attach screenshots and files), `Test Scenario from Text` / `from Image` (generates `AI` steps to apply to a sheet), `Generate Data List` / `Generate Data Table` / `Generate More Rows` (RVL maps), `AI Code Assistant` for JavaScript (8.6+, `@<file name>` adds files, `Apply` inserts at the cursor), `MCP Agent` (9.1+). [AI Chat](AI/ai_dashboard#ai-chat) · [Test Scenario from Text](AI/ai_dashboard#test-scenario-from-text) · [Generate Data Table](AI/ai_dashboard#generate-data-table) · [AI Code Assistant](AI/ai_dashboard#ai-code-assistant)

### AI in RVL

- AI Command: an `AI` row whose Object cell says what to do in plain words (`{name}` placeholders filled by `Param` rows). Rapise generates code once, caches it in `ai.commands.json` and replays it without AI until the text changes. Recommended order: Page Objects with high-level actions, learned objects, then AI Commands. [AI Command](AI/ai_command) · [Implementation](AI/ai_command#implementation) · [Recommended workflow](AI/ai_dashboard#overview)
- AI Panel: double-click an AI Command's line number or hover the cell and click `Show AI Panel` (also for a selected range); the toolbar button shows all AI Commands of the sheet. Per command: generate, AI edit (sparkles, 9.1+), play, open chat, thumbs up/down to save good and bad examples. Panel menu: generate all, run all, dock. [AI Panel](AI/ai_dashboard#ai-panel) · [How to Open](AI/ai_dashboard#how-to-open_1) · [Command Menu](AI/ai_dashboard#command-menu)
- In-place AI editing (9.1+): sparkles, type a correction such as `Use object ID: Login_Username`, Enter. Click an object ID to find it in the Object Tree (9.1+). [In-Place AI Editing](AI/ai_dashboard#in-place-ai-editing) · [Object Navigation](AI/ai_dashboard#object-navigation)
- RVL AI Assistant (9.1+): sparkles next to the test case title in the AI Panel; describe a change to the whole sheet, review the patch, `Apply`. [RVL AI Assistant](AI/ai_dashboard#rvl-ai-assistant)
- Steer generation: `##` prompt comment rows, `## #include`, `## #module` to include or exclude Page Objects (8.6+), `AIPrompt.txt` for rules applied to every command, `AIExamples.txt` from thumbs. Multiline commands: F2 then Enter, or `AI Command Multiline Mode` in Rapise Settings. [Prompt Comments](AI/ai_command#ai-prompt-comments) · [Including Modules](AI/ai_command#including-and-excluding-modules-page-objects) · [Shared Instructions](AI/ai_command#shared-instructions) · [Examples](AI/ai_command#tuning-with-positive-and-negative-examples) · [Multiline](AI/ai_command#editing-and-multiline-commands)
- AiTranslator (9.1+): in test cases tagged `airecorder`, `AI` steps become SmartActions automatically when the test runs; new objects come as a patch for the JSON Patch Editor. [AiTranslator](AI/aitranslator) · [Automatic Invocation](AI/aitranslator#automatic-invocation)

### AI at runtime

- AiRobot: the AI operates the application from screenshots for every run (`AiRobot.DoWebBrowser`, `DoFullScreen`, `DoWindow`); built in from 9.1, earlier imported as a public Page Object. [AiRobot](AI/airobot) · [Environment recommendations](AI/airobot#environment-recommendations)
- AiTester: ask the AI about text or screenshots during a run and assert on the answer (`DoTextQuery`, `DoWebImageQuery`, `AssertLastResponse`), generate data. [AiTester](AI/aitester) · [Assess application state](AI/aitester#assess-application-state)

### Agentic chat and MCP

- `MCP Agent` chat (9.1+): the AI plans and calls tools of the Rapise MCP server (test cases, runs, repositories, Page Objects) and the Spira MCP server (test cases, test sets, requirements, releases, runs, hosts). It works with Inflectra.ai, Amazon Bedrock, OpenAI and Azure OpenAI. [Agentic Chat with MCP](AI/agentic_mcp) · [Supported servers](AI/agentic_mcp#supported-mcp-servers)
- Which tools run without asking: AI Dashboard `Settings` > `MCP` tab, per tool `auto`, `ask` or `deny`; a switch turns a server on or off; `Always Approve` in a plan preview. Limits and timeouts are in the MCP Agent workflow (`mcp-agent.json`). [Tool approval](AI/agentic_mcp#tool-approval-policies) · [Configuration options](AI/agentic_mcp#configuration-options)
- External AI agents (an IDE assistant) reach Rapise through the MCP server: set `MCP Server Port` in `Settings > Global` (0 is off; one Rapise instance). [MCP Server](Guide/options_dialog#mcp-server)

## 13. When Something Goes Wrong

| The user says | What to try |
|---|---|
| "Object not found" / a step fails on an object | `Flash` the object in the Object Tree; `Re-Learn` it, or fix the locator in Web Spy maintenance mode; dynamic IDs: `WebAppProfile.json` rules; slow page: auto-waiting, `ObjectLookupAttempts`; let self-healing recover it and apply the patch, or `Test > Modernize` (9.1+). [Typical automation issues](Intro/automation#object-not-found) · [Object menu](Guide/object_tree#context-menu-object) · [Web Spy maintenance](Guide/web_spy#maintenance-mode) · [Web Application Profile](Guide/web_app_profile) · [Self-Healing](Guide/web_self_healing) |

[XPath in Web Spy](Guide/xpath#in-web-spy) · [Anchors](Guide/web_app_profile#anchors) · [CSS visibility](Guide/css#visibility-pseudo-classes) · [UIA issues](Guide/uiautomation_locator#common-issues) |

| A desktop app records nothing or the wrong things | Try another library (Auto, UIAutomation, Generic, third-party, Advanced Accessibility) with Shift+`Record` or `Tools > Libraries`; inspect with the matching spy. [Choosing a Windows library](Guide/windows_applications#choosing-the-right-windows-library) · [KB: actions not recorded](Manuals/kb#kb114-my-actions-are-not-recorded) · [KB: which library](Manuals/kb#kb133-the-recorder-asks-for-a-library-which-should-i-choose) |
| Java or Qt controls are not visible | Java Access Bridge; Qt accessibility plug-in. [Java Bridge](Guide/java_awt_swing_testing#java-bridge-installation) · [Qt](Guide/qt_framework_testing#usage) |
| The browser does not start, driver errors | `Test` the profile in `Settings > Selenium`; drivers download automatically (7.3+); use a `Selenium - Chrome` profile instead of old Chrome HTML. [Setting Up Selenium](Guide/setting_up_selenium) · [KB: connection to Chrome failed](Manuals/kb#kb652-resolving-connection-to-chrome-failed) · [Chrome](Guide/setting_up_web_browsers#chrome) |
| The test is too fast or flaky on timing | Auto-waiting (8.3+), `ObjectLookupAttempts`, slowing execution. [Auto-waiting](Guide/web_auto_waiting) · [KB: slow down execution](Manuals/kb#kb301-ways-to-slow-down-test-execution) |
| An optional popup breaks the test | SmartAction "Optional." or the RVL `?` flow. [Optional actions](Guide/web_smart_action#optional-actions) · [Conditional actions](RVL/Actions#conditional-actions) |
| Where do I see why it failed | Red rows in the report, filter by status, Errors view, higher `Verbose Level`, screenshot on failure. [Report Filtering](Guide/report_filtering) · [Errors View](Guide/errors_view) · [Verbosity](Guide/verbosity_levels) · [Screen Capture](Guide/settings_dialog#screen-capture) |
| The run stops at the first error / I want it to stop | `StopOnError` in Test Settings. [Execution](Guide/settings_dialog#execution) |
| The report does not open after a run | `Show Report` in Test Settings; `Last Report` in the Object Tree. [Execution](Guide/settings_dialog#execution) · [Test case menu](Guide/object_tree#test-case-context-menu) |
| A pane or view disappeared | `View > Show > ...`; reset the layout (hold Shift while starting Rapise, or `Settings > Global` > `Utilities` > `Reset Layout`). [Restoring the Default Layout](Guide/restoring_the_default_layout) |
| The RVL editor changes my text or does not autocomplete | F2 to edit without auto-correction; Tab to autocomplete; `Params` / Ctrl+P for optional parameters. [Disabling auto-correction](Guide/rvl_editor#disabling-cell-auto-correction) · [Auto-completion](Guide/rvl_editor#auto-completion) |

| My changes or new test cases are not in Spira | `Sync with Spira`. [Sync with Spira](Guide/spira_dashboard_2#sync-with-spira) |
